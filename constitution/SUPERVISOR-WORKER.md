# ProductOS — контур «Исполнитель + Супервизор»

> Исполнитель (Opus) делает работу.
> Денис + супервизор (Opus, редко) — читают дайджесты, улучшают систему.
> Отчёт системы = агрегат объективных фактов, не сочинение.

Команда целиком на Claude Opus в Claude Code. Две роли различаются **по функции**
(кто строит vs кто правит коробку), не по цене модели.

## Роли

### Исполнитель (Opus)
- Работает над проектами автономно, по задачам из бэклога
- Следует `team/core/engineering-discipline.md` и ролям из `team/agents/`
- Прогоняет экзамены из `team/evals/EXAMS.md` при изменениях
- В конце цикла генерирует `digest.md` — агрегат фактов + краткая самооценка
- Токены платные → делает по делу, без расточительства

### Супервизор (Денис + Opus)
- Раз в день/неделю читают один файл: `logs/digest-YYYY-MM-DD.md`
- Тратят 2 минуты: светофор → факты → расхождение с самооценкой → решения
- Правят «коробку»: промпты ролей, хуки, дисциплину, экзамены
- НЕ делают исполнительскую работу — только улучшение системы

Зачем разделять, если модель одна. Команда не может честно судить саму себя
(самообман). Супервизор смотрит на работу исполнителя свежим контекстом —
не как автор, а как проверяющий. Внешний судья = экзамены + приёмка Дениса.

## Что считается фактом (исполнитель не может подделать)

| Метрика | Источник | Как собрать |
|---|---|---|
| Экзамены сданы | `team/evals/EXAMS.md` + `SCORECARD-*.md` | счётчик PASS/PARTIAL/FAIL |
| Коммиты | `git log --oneline` | кол-во, откатов, переделок |
| Build-gate | `team/hooks/pre-push-build-gate.sh` | прошёл/не прошёл |
| Тесты | тест-раннер проекта | зелёные/красные, какие упали |
| DEBTS | `docs/DEBTS.md` | новых/закрытых, всего |
| Где циклил | `git log` (повторяющиеся сообщения) | счётчик «топчется» |

## Формат дайджеста

**Единый формат — в `team/core/DIGEST-TEMPLATE.md`.** Здесь не дублируем, чтобы не было двух разных шаблонов. Исполнитель пишет `logs/digest-YYYY-MM-DD.md` строго по нему.

Ключевое из шаблона: статус-светофор **по продукту** (не по механике) · объективные факты из `collect-facts.sh` (машина, не подделать) · колонка **«проверь сам»** (фальсифицируемо заказчиком за 30с) · 🚩 риск-флаги · самооценка (сверяем с фактами) · решение заказчика.

## Правило верификации

**Расхождение = сигнал.** Если самооценка «справился хорошо», а факты говорят
«3 экзамена завалены, 2 отката» — это красный флаг. Супервизор не ищет подвох,
но использует расхождение как индикатор, где докрутить промпт/роль/хук.

## Цикл работы

```
Исполнитель: получает задачу → работает → прогоняет гейты → собирает факты → пишет digest
Супервизор:  читает digest → сверяет факты vs самооценку → правит коробку → ставит новую задачу
```

## Когда исполнитель молчит

- Пустой digest (ничего не сделано) = 🔴, даже если самооценка «всё ок»
- Ошибка/зависание = автоматический флаг в дайджесте
- Система должна быть честной, даже когда нечего показать
