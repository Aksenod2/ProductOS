# Цель ProductOS — главный критерий

Это судья над процессом, ролями и инструментами. Любой спор решается **целью**, а не мнениями.

## Цель

**Автономная команда AI-агентов, которая надёжно делает качественные цифровые продукты
на любом проекте — и после каждого становится сильнее.**

Успех мерится **не объёмом сделанного**, а:
- **ростом системы** (после каждого проекта команда крепче), и
- **качеством продукта под приёмку Дениса**.

## Как этим пользоваться (правило решений)

- Любой вопрос — роль, процесс, инструмент, структура — решается одним тестом:
  **«приближает ли это к цели?»** Да → делаем. Нет → не делаем.
- **Личное мнение — не аргумент.** Ни Дениса, ни команды, ни оркестратора. Если мнение
  идёт вразрез с целью — оно не учитывается.
- **Денис задаёт цель** (миссию). Всё остальное выводится из неё, не из вкуса.
- Не скидывать решение на «как тебе удобнее» — выводить ответ из цели и обосновывать им.

## Примеры

- «Добавить роль под проект?» → только если это **универсальная** работа, нужная на любом
  проекте (служит цели). Проектный «вкус» существующей роли = лишний агент → против цели.
  (см. `FLOW.md`)
- «Срезать гейт ради скорости?» → нет: качество под приёмку — часть цели. (см. `PROCESS.md`)
