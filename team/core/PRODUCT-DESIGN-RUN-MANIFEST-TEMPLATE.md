## Контракты стыков

### Стык D1: сырой замысел владельца → product-architect

- **Класс:** свободный
- **Что передаётся:** исходная фраза, доступные материалы, ограничения и имя владельца
- **Формат:** `REQUEST.md` + `SOURCE-REGISTER.md` + ссылки на материалы
- **Валидация на входе:** архитектор подтверждает, что может сам предложить контур, ядро и области без готового списка от владельца
- **Что при ошибке:** один конкретный вопрос только о недоступном источнике или неоднозначном смысле; не просить владельца составить ядро

### Стык D2: product-architect → владелец по существенной развилке

- **Класс:** свободный
- **Что передаётся:** 2–3 варианта, последствия, рекомендация и один конкретный вопрос
- **Формат:** сообщение владельцу + запись в `DECISIONS.md`
- **Валидация на входе:** владелец видит различие вариантов и влияние на продукт, не проектирует варианты вместо команды
- **Что при ошибке:** архитектор уточняет варианты; без решения блокируется только зависимая часть карты

### Стык D3: product-architect → product-design-reviewer

- **Класс:** свободный
- **Что передаётся:** commit кандидата с Product Map, источниками, трассировкой,
  всеми подробными узлами и `DECISIONS.md` при наличии развилок либо отметкой
  `не применимо` в манифесте
- **Формат:** полный hash commit кандидата + весь каталог прогона; runtime ID
  автора и reviewer различаются; отчёт сохраняется в `reviews/<iteration>.md`
- **Валидация на входе:** reviewer проверяет файлы именно из указанного commit,
  целостность пакета, читаемость карты, ссылки на детали, честность неизвестного
  и точку остановки; отчёт содержит проверенный hash
- **Что при ошибке:** `NEEDS_REVISION` с координатами → исправляет архитектор; после двух одинаковых возвратов `BLOCK` владельцу

### Стык D4: product-architect → владелец

- **Класс:** свободный
- **Что передаётся:** готовая читаемая `PRODUCT-MAP.md` с ключевыми записями,
  рабочими ссылками `Подробности` и hash проверенного commit; при доступном Google
  Sheets — проектная копия v4 с Product Map, Реестром продукта и трассировкой
- **Формат:** обязательный `PRODUCT-MAP.md` в зафиксированном commit + сообщение
  передачи с hash; проектная Google Sheet того же снимка не заменяет Markdown-канон
- **Валидация на входе:** `scripts/validate-product-design-run.sh <run-dir>` подтверждает
  комплектность и совпадение run-каталога с commit; владелец понимает продукт по карте
  и открывает детали по ссылкам
- **Что при ошибке:** ответ владельца закрывает прогон; правки становятся входом нового прогона и не запускаются автоматически

## Критерии закрытия

- [ ] Отдел сам предложил ядро и области по сырому замыслу.
- [ ] Существенные развилки получили варианты, рекомендацию и ответ владельца либо открытый статус.
- [ ] Product Map читается без служебных кодов.
- [ ] Ключевое видно на карте, детали и источники доступны по ссылкам.
- [ ] Reviewer поставил `PASS`.
- [ ] Карта зафиксирована commit-ом и показана владельцу.
- [ ] При доступном Google Sheets создана проектная копия v4; мастер не изменён,
  Product Map, `CORE / JRN / STEP / CAP / LINK` Реестра продукта и трассировка
  согласованы с картой; `SLICE` и `USM` остаются за owner gate.
- [ ] После ответа владельца ничего не запущено автоматически.
