# MANIFEST отдела проектирования: Kanban pilot-01

- **Прогон:** `docs/product-design/pilot-01/`
- **Статус:** `prepared`
- **Сырой замысел:** `../../../REQUEST.md`, цитата «Мне нужна будет канбан-доска»
- **Владелец:** Денис
- **Dream Team:** ветка `experiment/project-design-bridge`; точный commit записать до запуска ролей
- **Каноническая карта:** `PRODUCT-MAP.md`
- **Дополнительное представление:** Google Sheet только при рабочих ссылках на детали; не обязательна
- **Существенные развилки:** `pending`
- **Текущий reviewer-отчёт:** `pending`
- **Правило снимка:** после `PASS` пакет фиксируется commit-ом; hash выдаёт
  машинная проверка и передаёт рядом с картой, но не записывает внутрь этого commit

## Граница прогона

- **Что проектируем:** продуктовый образ канбан-доски целиком на уровне Product Map.
- **Что известно на старте:** только сырой запрос из `REQUEST.md`.
- **Что отдел предлагает сам:** пользователей, контекст, ядро, области, путь и границы.
- **Когда спрашиваем Дениса:** только по существенным вариантам, уже подготовив последствия и рекомендацию.
- **Когда останавливаемся:** Product Map показана Денису; команда ждёт его решения.

## Контракты стыков

### Стык D1: сырой замысел Дениса → product-architect

- **Класс:** свободный
- **Что передаётся:** исходная фраза, доступные материалы, ограничения и имя владельца
- **Формат:** `REQUEST.md` + `SOURCE-REGISTER.md`
- **Валидация на входе:** архитектор подтверждает, что сам предложит контур, ядро и области без готового списка Дениса
- **Что при ошибке:** один конкретный вопрос о недоступном источнике или смысле; не просить Дениса проектировать ядро

### Стык D2: product-architect → Денис по существенной развилке

- **Класс:** свободный
- **Что передаётся:** 2–3 варианта, последствия, рекомендация и один конкретный вопрос
- **Формат:** сообщение Денису + запись в `DECISIONS.md`
- **Валидация на входе:** варианты различимы, влияние на продукт понятно, Денису не нужно проектировать их самому
- **Что при ошибке:** архитектор уточняет варианты; без решения блокируется только зависимая область карты

### Стык D3: product-architect → product-design-reviewer

- **Класс:** свободный
- **Что передаётся:** commit кандидата с Product Map, источниками, трассировкой,
  подробными файлами всех найденных областей и `DECISIONS.md` при наличии
  развилок либо отметкой `не применимо` в этом манифесте
- **Формат:** полный hash commit кандидата + весь каталог прогона; runtime ID
  автора и reviewer должны различаться; отчёт сохраняется как `reviews/NN.md`
- **Валидация на входе:** reviewer проверяет файлы именно из указанного commit,
  целостность, читаемость, ссылки на детали, честность неизвестного и точку
  остановки; отчёт содержит проверенный hash
- **Что при ошибке:** `NEEDS_REVISION` с координатами → исправляет архитектор; после двух одинаковых возвратов `BLOCK` Денису

### Стык D4: product-architect → Денис

- **Класс:** свободный
- **Что передаётся:** готовая `PRODUCT-MAP.md` с ключевыми записями, рабочими
  ссылками `Подробности` и hash проверенного commit; Google Sheet опциональна
- **Формат:** обязательный `PRODUCT-MAP.md` в зафиксированном commit + сообщение
  передачи с hash; при наличии — дополнительная Google Sheet того же снимка
- **Валидация на входе:** `scripts/validate-product-design-run.sh projects/kanban-product-design-pilot/docs/product-design/pilot-01`
  подтверждает комплектность и совпадение run-каталога с commit; Денис понимает
  продукт по карте и открывает детали по ссылкам
- **Что при ошибке:** ответ Дениса закрывает прогон; правки становятся входом нового прогона и не запускаются автоматически
