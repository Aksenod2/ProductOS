# RUNBOOK — опциональный учебный запуск в новом чате

Fixture не запущена. Инструкция ниже — только для отдельного явного решения
провести эксперимент в собственной учебной копии, не для клиентских исправлений.

## Команда для запуска

```text
Dream Team, запусти чистый пилот отдела проектирования для
projects/kanban-product-design-pilot. Начни только с REQUEST.md и не читай
готовые ответы других прогонов. Product Architect должен сам предложить
контур, ядро и области канбан-продукта и вести Product Map с первой итерации.
По существенным развилкам принеси мне 2–3 варианта, последствия и рекомендацию.
Все подробности, источники и решения сохрани в связанных файлах, а на карте
оставь ключевое человеческим языком. Перед показом карты запусти независимого
Product Design Reviewer. После показа Product Map жди моего решения и ничего
больше не запускай.
```

## Порядок

1. Прочитать `PROJECT.md`, `REQUEST.md`, `AGENTS.md` и этот файл.
2. Загрузить мастер-канон и две полные роли отдела.
3. Записать текущий commit ProductOS и runtime ID в `MANIFEST.md`.
4. Проверить манифест:
   `scripts/validate-epic-contracts.sh projects/kanban-product-design-pilot/docs/product-design/pilot-01`.
5. Запустить `product-architect` на уровне `lead`.
6. Если появляется существенная развилка, показать владельцу варианты и дождаться
   ответа; остальные области продолжать только там, где решение не требуется.
7. Зафиксировать готовый кандидат отдельным commit и передать его полный hash
   `product-design-reviewer` с другим runtime ID.
8. При замечаниях исправить только их, зафиксировать новый commit кандидата и
   запустить новое независимое ревью. Повторять до `PASS` или `BLOCK`.
9. Сохранить актуальный отчёт с проверенным hash, указать его в `MANIFEST.md`,
   перевести манифест в `ready_for_owner` и зафиксировать этот внутренний след
   отдельным commit, не меняя карту и узлы.
10. Запустить `scripts/validate-product-design-run.sh
    projects/kanban-product-design-pilot/docs/product-design/pilot-01`; проверка
    должна подтвердить актуальный `PASS`, разные runtime ID, неизменность карты
    после ревью и совпадение run-каталога с `HEAD`; затем вернуть hash без изменения файлов.
11. Показать Product Map владельцу вместе с этим hash и ждать его решения. Ничего
    не запускать дальше.

## Ожидаемый результат

- одна понятная Product Map;
- подробные файлы по всем найденным областям;
- реестр источников;
- варианты и решения владельца;
- служебная трассировка;
- независимый verdict;
- отсутствие PO, эпиков, требований, прототипа и кода.
