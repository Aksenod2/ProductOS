# ProductOS

Автономная команда AI-агентов на Claude Opus: строит цифровые продукты
(BA → PM → дизайн → код → QA), сама себя проверяет и после каждого проекта
становится сильнее. Под надзором Дениса.

## Структура

```
ProductOS/
├── constitution/
│   ├── SUPERVISOR-WORKER.md   ← контур: роли, факты, формат дайджеста
│   └── WORKER-PROMPT.md       ← промпт исполнителя
├── team/                       ← коробка команды (из OCS, обкатана)
│   ├── agents/                 ← 17 ролей
│   ├── core/                   ← дисциплина + шаблон CLAUDE.md
│   ├── hooks/                  ← предохранители (build-gate и др.)
│   ├── stakeholder/            ← журнал + уровни доверия
│   └── evals/                  ← 24 экзамена + скоркарта
├── scripts/
│   └── collect-facts.sh        ← сбор объективных метрик
├── projects/                   ← активные проекты (пока пусто)
├── logs/
│   ├── digest-*.md             ← дайджесты (читают супервизоры)
│   └── raw/                    ← сырые логи + facts JSON
└── memory/                     ← память системы (пока пусто)
```

## Как это работает

Команда живёт целиком на Claude Opus в Claude Code. Разделение — не по цене
модели, а по **функции**:

1. **Исполнитель (Opus)** — каждый цикл: собирает факты → работает по ролям
   (код/ревью/тесты/экзамены) → пишет дайджест.
2. **Супервизор системы (Денис + Opus, редко)** — читает `logs/digest-*.md` →
   сверяет факты vs самооценку → правит «коробку» (промпты ролей, хуки,
   дисциплину, экзамены). Не делает исполнительскую работу.

Внешний судья обязателен: команда не оценивает себя сама. Судья = экзамены
(`team/evals/`) + приёмка Дениса.

## Запуск

- Среда: **Claude Code** (Opus). От Hermes ушли.
- Автозапуск цикла исполнителя — через расписание (skill `schedule` / cron),
  не через внешний харнесс.
- Можно запускать цикл и вручную, когда нужно.

## Что нужно для старта

- Поместить проект в `projects/` — исполнитель начнёт работать над ним.
- Или: исполнитель прогоняет экзамены автономно как самопроверка.
